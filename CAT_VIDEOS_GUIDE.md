# Инструкция: Управление и замена видео с котиками в English Breakfast

В приложении English Breakfast видеоролики с котиками отображаются на обороте **Золотой карточки «Слово дня» (Word of the Day)**.
Видеосистема поддерживает два способа замены:
1. 🚀 **Замена «по воздуху» (OTA / Over-The-Air)** — моментально обновляет видео у всех пользователей через интернет **без пересборки APK/AAB и без проверки Google Play**.
2. 📦 **Локальная замена в исходниках** — для включения новых видео внутрь самого установочного файла приложения при очередной сборке релиза.

---

## 📁 Структура файлов и где что лежит

Единым источником правды для всех ассетов является папка **`frontend/`**:

```text
frontend/assets/video/
├── cat1.mp4                  # Видео для обычных дней недели
├── cat2.mp4
├── cat3.mp4
├── cat4.mp4
├── cat5.mp4
├── cat6.mp4
├── meme_monday_look.mp4      # Специальное видео 1 для понедельничного мема (кот смотрит в экран)
├── meme_monday_what.mp4      # Специальное видео 2 для понедельничного мема («Шо?! Опять понедельник?»)
├── ota_manifest.json         # Файл версий для обновления по воздуху
└── playlist.json             # Автоматически генерируемый список воспроизведения для карточки
```

> ⚠️ **Важно:** Никогда не редактируйте папки `docs/` или `android/.../public/assets/video/` вручную. Всегда работайте только в папке `frontend/assets/video/`, а синхронизация во все остальные директории проекта выполняется автоматически скриптом `node scripts/build.cjs`.

## 🎬 Требования к видеофайлам
Для максимальной плавности на всех смартфонах и экономии мобильного трафика:
* **Формат контейнера:** `.mp4`
* **Видеокодек:** H.264 / AVC (профиль Baseline или Main)
* **Аудиокодек:** AAC (стерео или моно, битрейт 96–128 kbps)
* **Разрешение:** Оптимально 720p (720x1280) или 540p (540x960)
* **Размер файла:** Желательно от 200 КБ до 700 КБ (не более 1.5 МБ)
* **Именование:** `cat1.mp4`, `cat2.mp4`, `cat3.mp4` и т.д. (строчные английские буквы).

## 🚀 СПОСОБ 1: Замена видео «по воздуху» (OTA) без выпуска AAB

Этот способ позволяет заменить ролик у пользователей в любой момент, даже когда приложение уже установлено из Google Play.

### Шаг 1. Подготовьте новый видеофайл
Например, вы хотите обновить `cat1.mp4` на новый ролик.

### Шаг 2. Разместите видеофайл
Есть два варианта размещения:
* **Вариант А (прямо в GitHub репозитории, рекомендуется):**
  Просто замените файл `frontend/assets/video/cat1.mp4` на ваш новый файл.
* **Вариант Б (на любом внешнем сервере / CDN / Firebase Storage):**
  Загрузите файл на ваш сервер и скопируйте прямую ссылку на `.mp4`.

### Шаг 3. Поднимите номер версии в `ota_manifest.json`
Откройте файл `frontend/assets/video/ota_manifest.json`.

* **Если используется Вариант А (файл в GitHub):**
  Увеличьте номер версии нужного ролика (например, с `1` на `2`):
  ```json
  {
    "versions": {
      "cat1.mp4": 2,
      "cat2.mp4": 1,
      "cat3.mp4": 1,
      "cat4.mp4": 1,
      "cat5.mp4": 1,
      "cat6.mp4": 1
    }
  }
  ```

* **Если используется Вариант Б (внешняя ссылка):**
  Увеличьте версию и укажите URL в секции `"urls"`:
  ```json
  {
    "versions": {
      "cat1.mp4": 2,
      "cat2.mp4": 1,
      "cat3.mp4": 1,
      "cat4.mp4": 1,
      "cat5.mp4": 1,
      "cat6.mp4": 1
    },
    "urls": {
      "cat1.mp4": "https://your-cdn.com/videos/new_cat1.mp4"
    }
  }
  ```

### Шаг 4. Запушьте изменения на GitHub
```bash
node scripts/build.cjs
git add .
git commit -m "ota: update cat1.mp4 to version 2"
git push origin main
```

### 🎉 Как это работает для пользователя:
1. При следующем запуске приложения фоновый сервис `videoService.js` скачает свежий `ota_manifest.json` с GitHub.
2. Обнаружив, что версия `cat1.mp4` стала `2` (а на устройстве `1`), приложение в фоне тихо скачает новый файл и сохранит его в изолированное локальное хранилище `CacheStorage` (`myduo-video-cache-v1`).
3. При открытии карточки дня пользователь увидит новое видео. Если интернет отключен, приложение надежно покажет базовую версию из APK.

## 📦 СПОСОБ 2: Локальная замена / добавление видео в новый AAB

Используйте этот способ, когда вы готовите новый релиз приложения в Google Play Console.

### Шаг 1. Скопируйте видео
Поместите ваши новые `.mp4` файлы в папку:
`frontend/assets/video/`

*Если вы хотите добавить новое видео, назовите его следующим по порядку номером, например `cat7.mp4`. Если хотите убрать — просто удалите ненужный файл из этой папки.*

### Шаг 2. Обновите манифест версий
В файле `frontend/assets/video/ota_manifest.json` приведите список ключей в соответствие с вашими файлами (версию для новых файлов поставьте `1`).

### Шаг 3. Запустите автоматическую сборку веб-ассетов
Выполните в терминале команду:
```bash
node scripts/build.cjs
```
Этот скрипт:
1. Автоматически просканирует `frontend/assets/video/` и найдет все файлы `cat*.mp4`.
2. Заново сформирует `playlist.json`.
3. Встроит актуальный массив видео в `index.html`.
4. Синхронизирует всё в папку `docs/` и корень проекта.

### Шаг 4. Проверьте тесты качества
```bash
npm test
```
Убедитесь, что все 62 теста (включая проверку целостности медиа и манифеста) успешно прошли (`pass 62, fail 0`).

### Шаг 5. Соберите подписанный Release AAB
Запустите команду сборки мобильного бандла:
```bash
node scripts/build_android_aab.mjs
```
Скрипт автоматически:
1. Скопирует ассеты в нативный Android-проект.
2. Выполнит `npx cap sync android`.
3. Запустит Gradle `bundleRelease` со сжатием ProGuard / R8 и подписью релизным ключом.
4. Поместит готовый бандл в корень проекта: **`EnglishBreakfast.aab`** и в папку `google_play_assets/EnglishBreakfast.aab`.

Готово! Файл `EnglishBreakfast.aab` можно сразу загружать в Google Play Console.

## 🧪 Как протестировать OTA-обновление на своем телефоне или в браузере

Если вы выложили новое видео по воздуху и хотите сразу увидеть обновление на тестовом устройстве, не дожидаясь естественного цикла:

1. **В браузере (Chrome DevTools):**
   * Откройте консоль (F12) -> вкладка **Application**.
   * В разделе **Storage** -> **Cache storage** вы увидите `myduo-video-cache-v1`. Там сохраняются скачанные OTA-видео.
   * Чтобы принудительно заставить приложение скачать видео заново, выполните в консоли:
     ```javascript
     localStorage.removeItem('ota_video_ver_cat1.mp4');
     location.reload();
     ```
2. **В установленном APK на телефоне:**
   * Просто откройте приложение при наличии интернета. В консоли/логах появится запись:
     `📥 [OTA Video] New version available for cat1.mp4 (v2 > v1). Downloading...`
     `✅ [OTA Video] cat1.mp4 updated to v2 successfully!`
   * При следующем перевороте карточки дня видео воспроизведется из кэша.

## ❓ Частые вопросы (FAQ)

* **Входят ли мемные видео понедельника (`meme_monday_look.mp4`, `meme_monday_what.mp4`) в обычную ротацию?**  
  Нет. Скрипт `build.cjs` исключает их из `playlist.json`. Они воспроизводятся исключительно по понедельникам в рамках специального мема подведения итогов недели.
* **Что произойдет, если у пользователя пропадет интернет во время скачивания OTA-видео?**  
  Скачивание прервется безопасно. Приложение продолжит показывать исходное видео из APK, а при следующем стабильном подключении повторит попытку.
* **Какое максимальное количество видео можно держать?**  
  Оптимально от 6 до 12 коротких роликов (общий вес папки видео в APK желательно держать в пределах 3–6 МБ, чтобы размер приложения в Google Play оставался легким: ~35 МБ).
