## 1. Эталон шапки приложения (`.mobile-header`) и строки состояния Android

Шапка приложения должна строго и неизменно соответствовать утверждённому эталону:

### Правила верстки хедера:
1. **Симметричные вертикальные отступы, центрирование и поддержка строки состояния:**
   ```css
   .mobile-header {
     display: flex;
     justify-content: space-between;
     align-items: center;
     padding: 10px 14px;
     min-height: 60px;
     height: auto;
     border-bottom: 1px solid var(--border-color);
     background: var(--card-bg, #ffffff);
     position: sticky;
     top: var(--safe-top, 0px);
     z-index: 50;
     box-sizing: border-box;
     flex-wrap: nowrap;
     overflow: hidden;
   }
   ```
2. **Окрашивание системной строки состояния (Status Bar) цветом основного фона:**
   - Строка состояния Android (где часы, батарея, Wi-Fi) **строго окрашивается в цвет основного фона приложения (`--bg-color`)**, а не сливается с хедером:
     - **Тёмная тема:** глубокий тёмный фон `#0f172a` (он темнее хедера `#1e293b`). Белые системные значки (`setAppearanceLightStatusBars(false)`).
     - **Светлая тема:** светлый фон `#f8fafc`. Тёмные системные значки (`setAppearanceLightStatusBars(true)`).
     - **Тетрадь:** винтажный кремовый фон `#f5eedc`. Тёмные системные значки (`setAppearanceLightStatusBars(true)`).
   - Точная высота статус-бара автоматически передаётся из Android в WebView через CSS-переменную `--safe-top`.
   - В верстке перед хедером размещается элемент `.safe-area-top-fill` с `height: var(--safe-top, 0px)` и фоном `var(--bg-color)`.
   - Хедер `.mobile-header` начинается на `top: var(--safe-top)` и имеет цвет плашки/карточки `var(--card-bg)` (`#1e293b` в тёмной теме), визуально возвышаясь над тёмной строкой состояния и сохраняя идеальную симметрию `min-height: 60px` и `padding: 10px 14px`.
   - В браузере `--safe-top = 0px`, `.safe-area-top-fill` имеет высоту `0px`, и хедер прилегает к верхнему краю окна (`top: 0`).

3. **Эталон нижней строки навигации Android (Navigation Bar) и безопасная зона снизу (`--safe-bottom`):**
   - **Режим Edge-to-Edge снизу:**
     - Нижняя строка навигации Android (полоска жестов или 3 кнопки «Назад / Домой / Меню») настраивается **полностью прозрачной**: `getWindow().setNavigationBarColor(Color.TRANSPARENT)`.
     - Фоновый цвет приложения (белый, тёмно-синий, кремовый) бесшовно доходит до нижнего края стекла устройства без инородных черных или серых полос-заглушек.
   - **Адаптивный контраст системной полоски жестов и кнопок:**
     - **Светлая тема (`#ffffff`)** и **«Тетрадь» (`#f5eedc`)**: системная полоска жестов и кнопки навигации окрашиваются в **тёмный цвет** (`WindowInsetsControllerCompat.setAppearanceLightNavigationBars(true)`).
     - **Тёмная тема (`#0f172a`)**: полоска жестов окрашивается в **белый цвет** (`WindowInsetsControllerCompat.setAppearanceLightNavigationBars(false)`).
   - **Безопасная зона контента (`--safe-bottom`):**
     - Интерактивные элементы (кнопки «Проверить», действия в модальных окнах, шторка меню, подвал контента) **никогда не должны перекрываться** полоской жестов или кнопками навигации, предотвращая случайные сворачивания приложения при нажатии.
     - Высота системной панели навигации замеряется нативно через `WindowInsetsCompat.Type.navigationBars()` и динамически передаётся в WebView в виде переменной `--safe-bottom`:
       - При жестовой навигации: `--safe-bottom` составляет `~16–24px`.
       - При навигации 3 кнопками: `--safe-bottom` составляет `~48–56px`.
       - В браузере (ПК / Web): `--safe-bottom` равен `0px` (или берется системный `env(safe-area-inset-bottom)`).
     - Основной контейнер контента (`.app-main-content`) использует:
       `padding-bottom: max(12px, var(--safe-bottom, env(safe-area-inset-bottom, 0px)));`
     - Шторка бургер-меню (`.burger-drawer`) использует:
       `padding-bottom: calc(16px + var(--safe-bottom, env(safe-area-inset-bottom, 0px))) !important;`

4. **Эталон элементов хедера и бургер-меню:**
   - **Бейдж рейтинга недели (`.header-xp-badge`):** иконка кристалла `.xp-badge-icon` строго `22px`, текст `.xp-badge-text` строго `14px`, обеспечивая деликатную, аккуратную посадку в шапке рядом с логотипом.
   - **Иконки бургер-меню (`.burger-drawer .tab-icon`):** оформляются строго в **монохромном нейтральном стиле** (`color: var(--text-muted)` в покое, `var(--text-main)` при наведении). Запрещено использовать разноцветные радужные иконки (зеленый/синий/красный/желтый) для пунктов меню.

## 2. Поведение вертикального скролла на страницах

1. **Контейнер контента (`.app-main-content` / `#app-content`):**
   ```css
   .app-main-content {
     flex: 1 1 auto;
     display: flex;
     flex-direction: column;
     padding: 10px 10px;
     padding-bottom: max(12px, var(--safe-bottom, env(safe-area-inset-bottom, 0px)));
     padding-left: max(10px, env(safe-area-inset-left, 0px));
     padding-right: max(10px, env(safe-area-inset-right, 0px));
     box-sizing: border-box;
     min-height: 0;
   }
   ```
2. **Экран не должен иметь паразитного вертикального скролла:**
   - Стартовый экран (Хаб тренировок: «Старт», «Выбрать категорию», «Повторить избранное») и карточки слов должны полностью помещаться в видимую область (`100% / 100dvh`) без прокрутки.
   - Запрещено добавлять искусственные завышенные паддинги снизу (например, `padding-bottom: 52px`), вызывающие появление полосы прокрутки.
   - Вертикальный скролл разрешён только естественным спискам (Словарь, Рейтинг, Статистика).
3. **Оптический баланс стартового экрана (Хаб тренировок):**
   - На экранах с карточкой «Слово дня» блок содержимого центрируется с оптическим подъёмом `transform: translateY(-44px)`.
   - Зазор между зелёными кнопками действий и карточкой «Слово дня» составляет строго `24px` (вместо прежних 36px), исключая визуальное «провисание» к нижней панели навигации и сохраняя симметричные безопасные поля сверху (`~68px`) и снизу (`~72px`).

4. **Стандарт интерактивной золотой карты «Слово дня» (`VIP WORD PASS` / `.bank-card.matte-gold`):**
   - Карточка «Слово дня» выполнена в премиальном форм-факторе банковской карты с золотым сечением (`aspect-ratio: 1.586 / 1`, макс. ширина 380px) и эффектом сатинового шлифованного золота (brushed micro-stripes + radial satin highlight + linear gradient).
   - **Рельеф и детализация:** По периметру карты проходит продавленная канавка `.card-inner-border` с эффектом фаски. В верхнем правом углу расположен объемный кабошон рубиново-бордового сердца в золотой оправе (`.card-fav`), в нижнем правом углу — объемный металлический шильдик в шампань-золоте (`.badge-tier`) с текущим уровнем слова (`ELEMENTARY`, `INTERMEDIATE` и др.).
   - **Центрирование:** Слово и транскрипция центрируются строго по центру свободного поля карты, без смещений к краям. Для слов любой длины шрифт адаптируется через `clamp(26px, 7vw, 40px)`.
   - **Интерактивность:**
     - Поддерживается тактильный 3D-наклон (Tilt & Parallax) при движении мыши / пальца с динамическим световым бликом (`.card-sheen`, `.card-glow`).
     - Плавный 3D-переворот на 180° открывает оборот карты с рельефным переводом и контекстным примером употребления.
     - Клик по сердечку изолирован (`e.stopPropagation()`) и переключает избранное без переворота карты.
     - Воспроизведение звука слова доступно по нажатию на иконку динамика в верхнем брендовом блоке и при возврате с оборота карты.

5. **Липкие элементы управления (Sticky Controls) во второстепенных разделах:**
   - Во всех вкладках с липкими блоками (Словарь `.dictionary-controls`, Избранное `.fav-sticky-controls`, Рейтинг `.leaderboard-sticky-group`, `.podium-sticky-wrapper`) смещение `top` задаётся строго с учётом высоты хедера и системной строки состояния:
     ```css
     top: var(--sticky-top, calc(60px + var(--safe-top, 0px)));
     ```
   - *Обоснование:* Фиксированные отступы `54px` или `58px` на Android приводят к тому, что при прокрутке панель поиска или кнопки заезжают под хедер на величину статус-бара (~32px).

6. **Корневое управление темами оформления (Light, Dark, Notebook):**
   - Корневой тег `<html>` (`document.documentElement`) и `<body>` всегда синхронно обновляют классы (`dark-theme`, `notebook-theme`) и фоновый цвет:
     - **Светлая тема:** `#f8fafc` (фон приложения и статус-бара, хедер — чистый белый `#ffffff`).
     - **Тёмная тема:** `#0f172a` (статус-бар и фон, хедер — `#1e293b`).
     - **Тетрадь:** `#f5eedc`.
   - Недопустимо оставлять устаревшие классы предыдущих тем на `<html>`.

7. **Нативная навигация Android: обработка кнопки «Назад» и жестов (System Back Navigation & Back Stack):**
   - Системная кнопка «Назад» Android (а также свайп «Назад» от края экрана) **категорически не должна сразу выбрасывать пользователя из приложения**, если он находится во внутренних разделах или модальных окнах.
   - **Строгая 4-уровневая иерархия возврата:**
     1. **Оверлеи и модалки:** Если открыта шторка бургер-меню (`#burger-drawer`) или любое модальное окно (авторизация, сканер, добавление слова, поздравление) — нажатие «Назад» закрывает оверлей. Экран под ним остаётся нетронутым.
     2. **Активная тренировка:** Если пользователь находится в процессе прохождения упражнений (карточки, тест, пары, конструктор, повторение избранного) — нажатие «Назад» возвращает его на Главный экран (Хаб тренировок), не сбрасывая глобальный прогресс.
     3. **Второстепенные вкладки:** Если пользователь находится на вкладках «Словарь», «Избранное», «Рейтинг», «Статистика» или «Настройки» — нажатие «Назад» переносит его на Главный экран («Тренировка»).
     4. **Главный экран (Хаб):** Только когда пользователь находится на самом Главном экране и возвращаться некуда, срабатывает защита от случайного выхода:
        - Показывается системное уведомление (Toast): *«Нажмите «Назад» еще раз, чтобы выйти»*.
        - При повторном нажатии в течение 2000 мс приложение корректно завершает работу (`finish()`).

## 3. Чек-лист перед внесением любых изменений и правила макетов

### 1. Железный принцип «Макет = Реальный код» (Zero-Mockup Fakes):
- ❌ **Категорически запрещено** при создании любых демонстрационных макетов (HTML-артефактов, эскизов интерфейса, прототипов) использовать самодельные или упрощенные текстовые заглушки хедера (например, `🍳 English Breakfast | ⚡ XP`).
- ✅ Любой макет экрана **обязан использовать 100% аутентичный канонический хедер из `AppLayout.js`**: оригинальный SVG-логотип «Чашка с книгой», кликабельный бейдж рейтинга недели (`💎 XP`), кнопку-бургер и класс `.mobile-header`.
- Пользователь принимает решения на основе макетов. Искажение базовых элементов интерфейса в макете приравнивается к поломке рабочего кода!

### 2. Обязательный чек-лист перед показом макета или коммитом:
Перед тем как отправлять макет пользователю или делать git commit:
- [ ] **Макеты:** Проверить, что в макете встроен 100% оригинальный SVG-логотип и разметка `.mobile-header` из `AppLayout.js`.
- [ ] **CSS:** Проверить `git diff` для `main.css`: нет ли изменений глобальных контейнеров (`body`, `.mobile-app`, `.mobile-header`, `.app-main-content`).
- [ ] **Шапка:** Убедиться, что шапка осталась строго симметричной, на `top: 0`, с `min-height: 60px`, `padding: 10px 14px` и `align-items: center`.
- [ ] **Скролл:** Убедиться, что экран (Хаб, Карточки) не имеет паразитного вертикального скролла на мобильных разрешениях (`100% / 100dvh`).
- [ ] **Фавикон и иконки:** Убедиться, что в вебе подключен фирменный фавикон («Чашка с книгой EN»), а в сборке Android APK (в `res/mipmap-*`) установлены фирменные сгенерированные иконки приложения, а не дефолтный синий крестик Capacitor.
- [ ] **Целостность данных и кодировки (Zero U+FFFD):** Убедиться, что в базе слов `words.json` отсутствуют повреждённые символы замены `\ufffd` (чёрные ромбы с вопросом ``), все переводы, транскрипции IPA и заметки являются валидным UTF-8.
- [ ] **Регрессия:** Убедиться, что любые новые доработки не затрагивают и не ломают ранее утверждённую верстку.

## 4. Правила сборки и размера Android APK (Build & Release Standards)

1. **Целевая папка для готового APK (Обязательное правило пользователя):**
   Готовый файл APK всегда должен сохраняться по пути:
   `C:\projects\my-duolingo-android\android\app\build\outputs\apk\EnglishBreakfast.apk`
   *(Дополнительно дублируется в корень `c:\projects\my-duolingo\EnglishBreakfast.apk` и `C:\projects\my-duolingo-android\EnglishBreakfast.apk`).*

2. **Эталонный размер и состав аудио в APK (~34–36 МБ):**
   - В APK обязательно упаковывается офлайн-озвучка **только начального уровня (Elementary — 2 445 слов)** и **строго только американского акцента (US)**.
   - **Неправильные глаголы (Irregular verbs)** в APK не зашиваются и загружаются пользователем по требованию.
   - **Британский акцент (UK)** в APK не зашивается и скачивается по требованию через модальное окно в Настройках.
   - Итоговый эталонный вес APK составляет **~34–36 МБ** (вместо прежних ~58 МБ).
   - Все остальные категории (Intermediate, Advanced, Patterns и др.) **никогда не упаковываются в APK**, а подгружаются пользователем по требованию из CDN (CacheStorage) прямо в интерфейсе приложения под текущий активный акцент.
   - Перед сборкой и синхронизацией `cap sync android` каталог `frontend/assets/audio` и `android/app/src/main/assets/public/assets/audio` подготавливаются скриптом `scripts/prepare_android_assets.mjs`.

## 5. Правила логики недельного рейтинга (Leaderboard Rules)

1. **Изоляция недельного рейтинга:**
   - Рейтинг недели («Лига недели») строго изолирован по ключу недели ISO: `YYYY-Www` (например, `2026-W38`).
   - При наступлении нового понедельника рейтинг каждого игрока **всегда начинается строго с 0 XP**.
2. **Категорический запрет на перенос общего XP в неделю:**
   - ❌ **Запрещено** подтягивать очки из общего накопительного ключа `localStorage.getItem('xp')` или ключей без суффикса недели при отсутствии очков за новую неделю.
   - Общий баланс очков за всё время существует только для шапки профиля и вкладки «За всё время» (`period = 'all'`).
   - Недельный рейтинг отражает исключительно очки, заработанные пользователем в течение текущей календарной недели (с понедельника 00:00 UTC по воскресенье 23:59 UTC).

## 6. Правила обучающего раунда и конвейера слов (Conveyor & Round Rules)

При нажатии кнопки **«🚀 Старт»** запускается обучающий раунд-конвейер по следующим утверждённым правилам:

### 1. Формирование батча раунда (до 15 слов):
- **Новые слова для изучения в Карточках:** до 10 новых слов текущей категории (не выученных и не находящихся в Избранном).
- **Интервальное повторение (подключаются в Квизе и Парах):** до 5 слов из «Избранного» этой категории (наиболее давно не повторявшиеся).
- **Добор пула повторения:** если слов в «Избранном» не хватает (меньше 5), недостающие места до 5 автоматически **добираются ранее выученными словами (*Mastered*)** этой же категории.

### 2. Этап 1: Карточки (Flashcards) — только новые слова:
- **В Карточках показываются ТОЛЬКО новые слова** батча (до 10 слов).
- ❌ **Слова из «Избранного» и выученные слова НИКОГДА не попадают в Карточки** — они уже знакомы игроку и подключаются сразу к этапам повторения (Квиз / Пары).
- **Индикатор раунда:** бейдж на карточке отображает позицию в текущем батче: **`🗂️ 1 / 10`**, **`🗂️ 2 / 10`** и т.д. (запрещено выводить устаревшие сквозные счетчики вроде `169 / 10`).
- **Развилка для игрока:**
  - **«Учить» (кнопка или свайп):** слово отправляется на полный цикл в **Квиз** (5 ступеней).
  - **«Знаю» (кнопка или свайп влево):** слово **минует Квиз** и сразу направляется на этап **Пары**, экономя время игрока на заучивание уже известных слов.

### 3. Этап 2: Квиз (Quiz) — 5 ступеней закрепления:
1. **Ступень 1 (En → Ru):** выбор правильного перевода строго из **6 вариантов ответов** на кнопках.
2. **Ступень 2 (Аудирование):** распознавание английского слова на слух без текста, выбор перевода из вариантов.
3. **Ступень 3 (Ru → En):** по русскому переводу выбор верного английского слова из вариантов.
4. **Ступень 4 (Спикинг / Произношение):** повторение слова голосом в микрофон с проверкой AI.
5. **Ступень 5 (Сборка слова — пропущенные согласные):** сборка слова из буквенных плиток. Буквы не перемешаны: гласные уже стоят на своих местах, а **согласные пропущены** и подставляются игроком.

### 4. Этап 3: Сопоставление пар (Matching Pairs) + 5 очков:
- Сюда приходят слова из Квиза (прошедшие 5 ступеней) и слова, помеченные в Карточках как «Знаю».
- Сетка слов и переводов с таймером раунда.
- **Начисление очков:** за успешное прохождение этапа Пар игроку начисляется **+5 очков (XP)**.

### 5. Этап 4: Тест / Диктант (Input / Spelling) — финальный экзамен:
- Ввод английского слова с клавиатуры по памяти буква за буквой (по переводу или диктовке).
- Требуется 2 безошибочных ввода.
- После сдачи Теста слово получает статус **🏆 Mastered (Выучено)**.

### 6. Финал раунда:
- По завершении всех слов батча: закрытие батча конвейера, начисление бонусных очков за раунд в общий и недельный лидерборд, победные фанфары 🎺 и показ карточки **«Слово Дня»** с золотой короной и видео.

## 7. Архитектура синхронизации данных и оптимизация квот (Local-First Sync Standards)

Для обеспечения мгновенного отклика (0 мс), поддержки офлайн-режима и предотвращения исчерпания суточных квот базы данных (ошибки `HTTP 429 Quota Exceeded`) действует строгий стандарт **Local-First (Offline-First)**:

### 1. Нулевая нагрузка на сеть во время игры (Zero Writes During Gameplay):
- При перелистывании карточек, ответах в квизе, сборке пар и вводе слов **запрещено отправлять отдельные сетевые запросы в Firestore**.
- Все изменения прогресса пишутся мгновенно и синхронно в локальную память (`localStorage` / SQLite).
- Это обеспечивает абсолютную плавность, отсутствие задержек и 100% работу без интернета (в самолете, метро).

### 2. Пакетная синхронизация строго по контрольным точкам (Milestone Batching):
Сетевая синхронизация прогресса с облаком инициируется **исключительно в трёх событиях**:
1. **Финиш обучающего раунда:** при показе карточки победы и фанфар вызывается `pushUserDataToCloud(null, null, true)` (ровно **1 пакетный запрос** на весь раунд вместо сотен запросов).
2. **Сворачивание/пауза приложения:** обработчики `visibilitychange`, `pagehide`, `beforeunload` и нативный Android-хук `pause` сбрасывают буфер в облако.
3. **Перед выходом из аккаунта (`pre_logout`):** гарантирует сохранение всех набранных очков и выученных слов перед закрытием сессии.

### 3. Агрегация документов (1 документ вместо тысяч):
- Весь массив прогресса (1300+ слов) сохраняется в **1 единый документ** `users/{userId}/data/progress` (`saveBulkProgressFirestore`).
- ❌ **Категорически запрещено** создавать циклы записи отдельных документов на каждое слово (`users/{userId}/progress/{wordId}`). Это сжигает квоту за считанные минуты.

### 4. Защита от спама и пустых операций:
- ❌ **Запрещен фоновый сессионный таймер (heartbeat):** регулярная отправка пустых запросов каждые 45 секунд вырезана.
- ❌ **Запрещена запись сессий гостей:** для неавторизованных профилей (`guest_...`) любые сетевые запросы аналитики в Firestore блокируются.

### 5. Гарантия 100% восстановления состояния при авторизации:
При входе пользователя в аккаунт на любом устройстве из Firestore обязаны полностью восстанавливаться:
- **Рейтинг недели (XP):** авторитетный максимум очков текущей недели (запрещено обнулять очки $\ge 4000$).
- **Массив прогресса (Progress):** все изученные слова, статусы Mastered, счетчики ошибок и даты практики.
- **Избранное (Favorites):** весь список слов со звездочкой.
- **Язык интерфейса (`interfaceLang`):** восстанавливается и переводит интерфейс через `myduo:lang_changed`.
- **Тема оформления (`theme`):** восстанавливается (`light`, `dark`, `notebook`) и накладывает CSS-классы на `body`.
- **Метки скачанных медиафайлов (`downloadedCategories`):** переносятся в облако, чтобы приложение никогда не предлагало скачать то, что пользователь уже загружал ранее.
- **Статистика:** рассчитывается динамически из восстановленного прогресса (точность %, выученные слова, серия дней ударного режима).

## 8. Дорожная карта масштабирования до 100 000+ пользователей (High-Load Roadmap)

Для масштабирования на 100 000 активных пользователей (DAU) утверждены следующие архитектурные принципы:

### 1. Текущие возможности пакетного Local-First подхода:
- При переходе на пакетную запись (1–2 запроса на раунд) суточный лимит бесплатного тарифа Firebase Spark (20 000 записей/день) выдерживает **до 6 000 – 10 000 раундов в день** (вместо 12 пользователей ранее).
- На платном тарифе Firebase Blaze (Pay-as-you-go) при стоимости $0.18 за 100 000 записей обслуживание 100 000 пользователей стоит всего **~$25–30 в месяц**.

### 2. Устранение единой точки отказа Лидерборда (Single Point of Contention):
Хранение всех участников недели в одном документе `leaderboard_{weekKey}` имеет предел: лимит Firestore в 1 запись/сек на документ и максимальный размер 1 МБ (максимум ~6 000 участников).

**План масштабирования лидерборда на 100 000+ игроков:**
1. **Решение A (Геймдев-стандарт Duolingo — Лиги по 30 человек):**
   - Пользователи при старте недели распределяются по виртуальным «комнатам» (когортам) по 30 игроков: `leaderboard_{weekKey}_room_{roomNumber}`.
   - Размер документа комнаты: всего 2–3 КБ.
   - Отсутствие конкуренции за запись, нулевая нагрузка на сервер, высочайшая мотивация игроков бороться за топ-3 в своей лиге.
2. **Решение B (Коллекция документов Firestore):**
   - Перевод участников в подколлекцию: `leaderboards/{weekKey}/players/{userId}`.
   - Каждый игрок обновляет только свой персональный документ.
   - Экран рейтинга запрашивает топ-50 игроков по индексу: `.orderBy('xp', 'desc').limit(50)`. Запрос выполняется за 15 мс вне зависимости от общего числа игроков (хоть 1 000 000).

## 11. Стандарты целостности данных и кодировки (Data Integrity & UTF-8 Encoding Standards)

Для исключения ситуаций, когда в интерфейсе отображаются знаки вопроса в черных ромбах (символ замены `U+FFFD` / ``), действует строгий стандарт контроля кодировки:

### 1. Категорический запрет на символы `U+FFFD` (`\ufffd`):
- В базе слов (`words.json`), словарях, файлах локализации, транскрипциях и примечаниях **категорически запрещено наличие повреждённых байтовых последовательностей UTF-8 и символов `\ufffd`**.
- Источник проблемы: неаккуратный экспорт CSV/Google Sheets с разрывом многобайтовых последовательностей (кириллица, греческий алфавит, знаки долготы и звуков в транскрипциях IPA `ː`, `ɔ`, `ə`, `ɪ`).
- Любые изменения базы слов обязаны проходить валидацию перед коммитом и сборкой.

### 2. Автоматическая валидация при сборке (Build Gatekeeper):
- Скрипты сборки (`scripts/build.cjs` и `scripts/prepare_android_assets.mjs`) обязаны проверять файлы данных на отсутствие `\ufffd`.
- При обнаружении хотя бы одного символа `\ufffd` сборка немедленно **прерывается с ошибкой**, выводя предупреждение:
  ```javascript
  const rawWords = fs.readFileSync(wordsPath, 'utf8');
  if (rawWords.includes('\ufffd')) {
    throw new Error('❌ BUILD FAILED: Detected corrupted UTF-8 replacement character (U+FFFD) in words.json!');
  }
  ```

### 3. Двухуровневая защита (Defense-in-Depth):
1. **Уровень хранения данных (Static Integrity):** В репозитории и релизных сборках база слов `words.json` должна содержать 0 повреждённых символов (`remainingCorrupt = 0`).
2. **Уровень рендеринга (Runtime Sanitizer):**
   - Функция получения перевода (`getWordTranslation` в `i18n.js`) и компоненты карточек обязаны содержать защитную санитаризацию.
   - Если в рантайме обнаружен `\ufffd` в одном из языковых полей `translations[lang]`, система обязана автоматически переключиться на чистый резервный перевод (`wordObj.translation`) либо корректно отфильтровать битый символ, не допуская появления чёрного ромба на экране пользователя.

## 12. Стандарты первого запуска, выбора акцента и подкачки аудио (Onboarding & Audio Delivery Standards)

Для обеспечения максимальной экономии интернет-трафика и памяти смартфона игрока, а также минимального размера APK-файла (~34–36 МБ), утверждён следующий обязательный регламент:

### 1. Сценарий первого запуска (First Launch & Onboarding):
1. **Экран «Настройки» при первой установке:**
   - При первом открытии приложения (до перехода к тренировкам) игрок попадает в меню **«Настройки»** для первоначальной конфигурации.
2. **Американский акцент по умолчанию (Default US):**
   - По умолчанию предустановлен и выбран **«🇺🇸 Американский»** акцент.
   - Для американского акцента все 2 445 слов базового уровня «Начальный» уже зашиты в APK и работают офлайн без интернета.
3. **Выбор Британского акцента (UK Accent Modal):**
   - Если игрок переключает выбор на **«🇬🇧 Британский»**, **только в этот момент** появляется фирменное модальное окно загрузки (по аналогии с модальным окном скачивания категории).
   - Окно предлагает скачать британский аудиопакет для уровня «Начальный» (~20 МБ) с отображением живого прогресс-бара.
   - При отмене переключатель возвращается на Американский.

### 2. Правило одноакцентной подкачки категорий (Single-Accent On-Demand Download):
1. **Неправильные глаголы (Irregular verbs) и старшие уровни:**
   - Никакие категории, кроме базового Elementary US, не зашиваются в APK.
2. **Скачивание только активного акцента игрока:**
   - При скачивании любой категории («Неправильные глаголы», «Средний», «Продвинутый» и др.) загружается **только аудиофайл текущего выбранного акцента игрока** (если активен US — скачивается только US; если UK — только UK).
   - ❌ **Категорически запрещено** скачивать оба акцента одновременно, если пользователь использует только один из них. Это сокращает размер загрузки на 50% и бережёт память смартфона.
3. **Смена акцента в процессе использования:**
   - Если пользователь позже решает сменить акцент в Настройках, приложение предлагает подкачать недостающий акцент только для уже активных/скачанных категорий.
4. **Стандарт выбора категории и модального окна загрузки озвучки:**
   - Единственной категорией, считающейся встроенной в пакет APK (`isBundled`), является **строго и исключительно `Elementary` (US)**.
   - ❌ **Категорически запрещено** добавлять категорию «Неправильные глаголы» (`Irregular verbs`) или любые другие категории в список встроенных (`isBundled`).
   - При выборе игроком любой категории, кроме `Elementary` (включая «Неправильные глаголы», «Паттерны», `Intermediate`, `Advanced`), система обязана проверять наличие скачанной озвучки (`isCategoryAudioDownloaded`) и при её отсутствии **всегда показывать фирменное модальное окно загрузки аудиопакета** (`#cat-voice-download-modal`) с индикатором прогресса.

### 3. Канонический стандарт сборки Android APK (Strict Build Pipeline & Zero-Bloat Standard):
- ❌ **КАТЕГОРИЧЕСКИЙ ЗАПРЕТ НА РУЧНУЮ СБОРКУ И ВЫЗОВ GRADLEW НАПРЯМУЮ:**
  Сборка Android APK **строго и исключительно** должна производиться через канонический скрипт:
  ```bash
  node scripts/build_android_apk.mjs
  ```
  **Никаких ручных `gradlew assembleDebug`, `npx cap sync` или разрозненных вызовов команд!**
- ⚠️ **Причина запрета (Gradle Incremental Archive Bloat):**
  Если вызывать Gradle напрямую (`gradlew assembleDebug`), упаковщик Gradle обновляет существующий архив `app-debug.apk` инкрементально поверх старого файла без усечения (truncate). Если в предыдущей сборке присутствовали другие аудиопакеты (UK или старшие уровни), в файле APK остаётся скрытая «мёртвая зона» (gap) пустых байт размером до 100 МБ. В результате размер APK раздувается со штатных ~30 МБ до 130 МБ!
- ✅ **Обязательные этапы, которые автоматически гарантирует `build_android_apk.mjs`:**
  1. **Валидация целостности данных:** `node scripts/build.cjs` в корневом проекте (проверка на отсутствие поврежденных символов UTF-8 `\ufffd`).

## 13. Стандарты жизненного цикла запуска и Сплэш-экрана (Startup & Splash Lifecycle Standards)

Для обеспечения премиального пользовательского опыта и исключения визуального шума при открытии приложения действует фундаментальный принцип:

> [!IMPORTANT]
> **ПРИОРИТЕТ ЧИСТОГО ВИЗУАЛА НАД СКОРОСТЬЮ ОТКРЫТИЯ:**
> **«Пусть лучше дольше показывает белое окно с логотипом при загрузке, чем показывает главное окно без наполнения, а затем на глазах пользователя подгружает карточки и кнопки!»**

### 1. Эталонный пайплайн запуска приложения:
1. **Первичный Сплэш-экран (`#app-splash-screen`):**
   - Отображается на чистом белом фоне (`#ffffff`) с фирменным SVG-логотипом («Чашка с книгой») и плавной полосой индикации.
   - Сплэш полностью изолирован от кликов (`pointer-events: none`), исключая случайные нажатия до готовности приложения.
2. **Гарантированное завершение инициализации данных (`await loadData()`):**
   - Загружаются слова из базы данных, настройки профиля, избранное, облачные данные пользователя и ID Слова дня (`cloudWordOfTheDayId`).
   - Исходный сплэш **категорически запрещено скрывать** до завершения `loadData()`.
3. **Полный рендеринг активного экрана (`await renderTab(activeTab)`):**
   - Вызов `renderTab(activeTab)` **строго предваряется `await`**.
   - До скрытия сплэша в DOM должны быть полностью построены:
     - Шапка с аватаром и бейджем рейтинга недели (`updateHeaderUser()`).
     - Главный экран (Хаб) со всеми кнопками («🚀 Старт», «📚 Выбрать категорию», «⭐ Повторить избранное»).
     - Интерактивная Золотая карта «Слово дня» с актуальным словом, транскрипцией, сердечком и шильдиком уровня.
4. **Минимальный таймер стабильности и двухкадровый рендеринг (Double RAF):**
   - Для предотвращения резких вспышек при сверхбыстрой загрузке действует минимальный интервал стабильности (`450 мс`).
   - Перед вызовом `hideAppSplashScreen()` выполняется двойной цикл `requestAnimationFrame(() => requestAnimationFrame(...))`, гарантирующий, что браузер рассчитал стили, выполнил reflow и полностью отрисовал готовый кадр в видеобуфер экрана.
5. **Бесшовный переход:**
   - Сплэш плавно затухает через `opacity: 0; transition: opacity 0.25s ease;`.
   - Пользователь сразу видит готовый к работе, стабильный интерфейс без «прыгающих» кнопок и пустых экранов.

### 2. Защита от повторных миганий и перерисовок:
- Фоновые события синхронизации (`cloud_synced`, `progress_updated`) при старте приложения **не должны сбрасывать или перерисовывать DOM уже отображённого Хаба**, если структура карточки и данные идентичны.

## 14. Эталон экрана «Статистика» (Statistics Screen Standards)

Экран «Статистика» спроектирован для мгновенного считывания прогресса без необходимости вертикального скролла на подавляющем большинстве мобильных устройств:

### 1. Верхние плашки KPI (Сетка 1×3):
- **Сверхкомпактный формат в одну строку:**
  - Плашки располагаются строго в 1 горизонтальный ряд из 3 колонок: `[🎓 821]`, `[🎯 97%]`, `[🔥 18 дн]`.
  - Громоздкие подстрочные текстовые подписи убраны. Значение выводится рядом с иконкой, что экономит вертикальное пространство.
- **Абсолютная симметрия внешних полей:**
  - **Отступ сверху** (над плашками KPI): строго **`10px`** (`padding-top: 10px` у контейнера `.app-main-content` при `margin-top: 0` у `#stats-content`).
  - **Отступ снизу** (под плашками KPI до блока программы): строго **`10px`** (`margin-bottom: 10px` у `.stats-grid` во всех медиа-запросах).
  - Сверху и снизу от плашек KPI образуется строго симметричное, чистое поле.

### 2. Блок категорий программы (`.curriculum-block`):
- Имеет фиксированную посадку `flex-shrink: 0; margin-bottom: 10px;`.
- Отображает аккуратные компактные карточки категорий с миниатюрными прогресс-барами.

### 3. «Резиновый» (эластичный) график динамики (`.chart-card`):
- **Эластичный контейнер:**
  ```css
  .chart-card {
    flex: 1 1 auto;
    min-height: 110px;
    display: flex;
    flex-direction: column;
    margin-top: 0;
    margin-bottom: 0;
  }
  .chart-svg-container {
    flex: 1 1 auto;
    min-height: 0;
    width: 100%;
    position: relative;
    overflow: hidden;
  }
  ```
- **Адаптивность под геометрию смартфона:**
  - На длинных, вытянутых смартфонах (современные экраны 20:9, 19.5:9) график эластично растягивается вниз, заполняя всё свободное пространство до нижнего навбара.
  - На компактных смартфонах график аккуратно поджимается без появления полосы вертикального скролла.
- **Динамический расчёт SVG через `ResizeObserver`:**
  - Векторный график пересчитывает Y-координаты уровней сетки, высоты столбцов дневного прогресса и узлы накопительной линии под фактическую высоту контейнера.
  - Встроена защита от микроколебаний (перерисовка происходит только при изменении высоты более чем на 2px: `Math.abs(measured - lastHeight) >= 2`).

## 15. Паспорт интерактивной Золотой карты «Слово дня» (`VIP WORD PASS` / `.bank-card.matte-gold`)

Золотая карта «Слово дня» — центральный премиальный визуальный якорь приложения English Breakfast, сочетающий эстетику люксовой металлической карты и геймифицированную интерактивность:

### 1. Геометрия и пропорции:
- **Золотое сечение:** пропорции строго соответствуют международному стандарту банковских карт ID-1 (`aspect-ratio: 1.586 / 1`, макс. ширина 380px).
- **Скругление углов:** строго **`22px`** (`border-radius: 22px !important;` для карты и обеих граней `.flashcard-face`), создающее премиальный вид золотой VIP-карты банка.

### 2. Материал и отделка:
- **Сатиновое шлифованное золото (Brushed Satin Gold):**
  - Многослойная композиция: линейные микрополосы фактуры брашированного металла + радиальный сатиновый блик + благородный тёплый золотой градиент (`#713f12` → `#a16207` → `#ca8a04` → `#eab308` → `#854d0e` → `#451a03`).
  - Тонкий металлический кант: граница `1.2px solid rgba(253, 224, 71, 0.65)` с верхним световым отблеском `rgba(255, 255, 255, 0.85)`.
  - Вдавленная фаска `.card-inner-border` по внутреннему периметру с эффектом прецизионной гравировки.

### 3. Элементы лицевой стороны (Front Face):
- **Верхний левый блок:** надпись `VIP WORD PASS` с микро-логотипом и кнопкой аудиодинамика для прослушивания эталонного произношения.
- **Верхний правый угол (Рубиновый кабошон):** объемная кнопка «В избранное» (`.card-fav`) в виде глубокого рубиново-бордового сердца в полированной золотой оправе.
  - ⚠️ Клик по сердечку строго изолирован (`e.stopPropagation()`) — добавление в избранное не вызывает переворот карты.
- **Нижний правый угол (Металлический шильдик):** рельефный шильдик в золоте шампань (`.badge-tier`) с текущим уровнем слова (`ELEMENTARY`, `INTERMEDIATE`, `ADVANCED`).
- **Оптический центр карты:** английское слово и фонетическая транскрипция в квадратных скобках `[ ... ]` центрируются строго по центру свободного поля.
- **Адаптивный размер шрифта:** `clamp(26px, 7vw, 40px)` гарантирует идеальную читаемость для слов любой длины без переносов и вылетов за пределы карты.

### 4. Физика 3D и интерактивность:
- **Тактильный 3D-наклон (Tilt & Dynamic Sheen):** при движении курсора мыши или пальца по экрану карта наклоняется с плавным параллаксом, а по поверхности скользит динамический световой блик (`.card-sheen`, `.card-glow`).
- **3D-переворот на 180° (Flip):** тап по свободному полю карты плавно переворачивает её на оборотную сторону.
- **Оборотная сторона (Back Face):** выполнена в единой золотой стилистике и содержит рельефный перевод на русский язык и контекстное предложение-пример с выделенным словом и кнопкой озвучки.

## 16. Правила контроля репозиториев и версионирования APK (Git & Release Integrity)

1. **Запрет на коммит `.apk` файлов в git:**
   - Бинарные файлы Android APK (`EnglishBreakfast.apk`, `app-debug.apk`) **никогда не должны коммититься в репозиторий Git**.
   - Они обязаны быть зафиксированы в `.gitignore` обоих репозиториев (`my-duolingo` и `my-duolingo-android`).
2. **Предотвращение превышения лимита GitHub (100 MB Limit):**
   - GitHub блокирует пуши (pre-receive hook), содержащие любые единичные блобы более 100 МБ.
   - Сборка через `node scripts/build_android_apk.mjs` гарантирует чистый размер APK **~29.9–34 МБ**.
   - При любых изменениях перед отправкой обязательно проверяется `git status`, чтобы в коммит попадали только файлы исходного кода, стилей и документации.
