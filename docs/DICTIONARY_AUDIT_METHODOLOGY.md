# Регламент и Строгая Методика Аудита Словаря English Breakfast

> **Версия стандарта:** 1.0 (Gold Standard)  
> **Область применения:** 7 017 слов и выражений во всех 36 поддерживаемых локалях.  
> **Единый источник правды:** `frontend/assets/data/words.json` $\rightarrow$ синхронизация в `docs/` и корень через `node scripts/build.cjs`.

---

## 1. Фундаментальные принципы и правила проекта

### 1.1. Правило 36 локалей (Strict 36 Locales)
Словарь официально и бескомпромиссно поддерживает **ровно 36 локалей**:
* **Славянские:** `ru`, `uk`, `pl`, `cs`, `sk`, `bg`, `hr`, `sl`
* **Германские:** `en` (US/UK), `de`, `da`, `sv`
* **Романские:** `fr`, `es` (включая мексиканские стандарты), `it`, `pt` (включая бразильские стандарты), `ro`
* **Эллинистическая:** `el`
* **Балтийские:** `lt`, `lv`
* **Финно-угорские:** `fi`, `et`, `hu`
* **Тюркские:** `tr`, `kk`
* **Восточноазиатские:** `zh` (упрощенный китайский), `ja`, `ko`
* **Юго-Восточная Азия:** `vi`, `th`, `id`
* **Индоарийские:** `hi`, `bn`
* **Семитские и RTL:** `ar` (арабский), `fa` (персидский), `ur` (урду)

*(Языки `mt` мальтийский и `ga` ирландский окончательно исключены из проекта).*

### 1.2. Запрет несанкционированных сборок APK / AAB
Никогда не запускать сборку `EnglishBreakfast.apk` или `EnglishBreakfast.aab` в ходе аудита словаря, если пользователь явно не отдаст такую команду.

### 1.3. Синтаксическая чистота текста (Zero Noise Policy)
В поле перевода **категорически запрещены**:
* ❌ Любые круглые скобки `()` (включая грамматические пометы `(сущ.)`, `(глагол)`, `(según contexto)`).
* ❌ Точки с запятой `;` и `؛`.
* ❌ Слэши `/` (включая разделители рода `он/она`, `chciałbyś/chciałabyś`).
* ❌ Заглушки `#N/A`, `undefined`, `null`, `TODO`, знаки вопроса `?`.
* ❌ Поврежденные символы юникода `U+FFFD` ().
* ❌ Дубликаты синонимов через запятую (`vlak, vlak` $\rightarrow$ `vlak, trenirati`).

**Разделители синонимов по письменностям:**
* Для LTR-языков: запятая с пробелом (`, `).
* Для RTL (арабский, персидский, урду): арабская запятая с пробелом (`، ` / `\u060C `).
* Для китайского и японского: перечислительная запятая (`、` / `\u3001`).

## 2. Методика аудита неправильных глаголов (Irregular Verbs)

В словаре содержится ровно **218 неправильных глаголов**.

### 2.1. Стандарт заголовка (`word`)
* В поле `word` записывается английская триада через пробел:  
  👉 `V1 V2 V3` (например: `freeze froze frozen`, `take took taken`, `win won won`).
* Никаких слэшей в формах прошедшего времени (`born/borne` $\rightarrow$ `born`).

### 2.2. Стандарт перевода (`translation` и `translations.*`)
* **В переводе допускается ТОЛЬКО первая форма — чистый инфинитив / словарная форма!**  
  *Пример:* для `take took taken`:
  * `ru`: **брать** (не *«брал, взятый»*)
  * `de`: **nehmen** (не *«nahm, genommen»*)
  * `es`: **tomar, llevar** (не *«tomó, tomado»*)
  * `fr`: **prendre** (не *«pris»*)
  * `ja`: **取る** (словарная форма на *-u*)
  * `ko`: **취하다** (словарная форма на *-da*)

### 2.3. Контроль лексической омонимии глаголов
Обязательная ручная сверка контекста:
* `lie lay lain` $\rightarrow$ «лежать» (не путать с *lie lied lied* — «лгать»).
* `wind wound wound` $\rightarrow$ «наматывать, заводить часы, извиваться» (не путать с существительным *wind* — «ветер»).
* `bear bore born` $\rightarrow$ «выносить, терпеть, рождать» (не путать с существительным *медведь*).
* `tear tore torn` $\rightarrow$ «рвать, разрывать» (не путать со слезой).

## 3. Методика аудита идиом, поговорок и разговорных паттернов

В словаре свыше **180 устойчивых выражений и поговорок**.

### 3.1. Детекция и устранение буквальных машинных калек (Calque Detection)
Скрипт проверки сравнивает семантические маркеры. Перевод бракуется как «ложная калька», если в переводе присутствуют буквальные слова-образы из английского, которых нет в живой культуре языка перевода:

| Английский паттерн | Буквальная машинная калька (БРАК) ❌ | Аутентичный народный эквивалент (СТАНДАРТ) ✅ |
| :--- | :--- | :--- |
| `kill two birds with one stone` | «убить двух птиц одним камнем» | **«одним ударом убить двух зайцев»** (RU), *«zwei Fliegen mit einer Klappe schlagen»* (DE) |
| `spill the beans` | «рассыпать бобы/фасоль» | **«выболтать секрет, проболтаться»** (FR: *vendre la mèche*) |
| `hit the books` | «бить книги / ударить книги» | **«засесть за учебу, зубрить»** |
| `every cloud has a silver lining` | «у облака серебряная подкладка» | **«нет худа без добра»** (ES: *no hay mal que por bien no venga*) |
| `when pigs fly` | «когда свиньи полетят» | **«когда рак на горе свистнет, никогда»** (RU), *«cuando las ranas críen pelo»* (ES), *«في المشمش»* (AR) |
| `no pain no gain` | «нет боли нет выгоды» | **«без труда не выловишь и рыбку из пруда»** (RU), *«bez práce nejsou koláče»* (CS) |

### 3.2. Формула «Двойного толкования» (Didactic Dual Formula)
Для максимальной пользы обучающихся в карточках сложные идиомы формулируются по принципу:  
👉 **`[Культурная поговорка], [Прямой функциональный смысл]`**

*Примеры:*
* `when pigs fly` $\rightarrow$ `когда рак на горе свистнет, никогда`
* `no pain no gain` $\rightarrow$ `без труда не выловишь и рыбку из пруда, без усилий нет результата`
* `better safe than sorry` $\rightarrow$ `семь раз отмерь один отрежь, лучше перестраховаться`

### 3.3. Разговорные речевые клише
Разговорные фразы должны звучать на 100% естественно:
* `I mean it` $\rightarrow$ «я серьезно» *(не «я имею это в виду»)*.
* `Here you go` $\rightarrow$ «вот, пожалуйста» *(не «здесь ты идешь»)*.
* `It slipped my mind` $\rightarrow$ «вылетело из головы, забыл» *(не «мой разум соскользнул»)*.
* `Not too shabby` $\rightarrow$ «весьма неплохо, прилично» *(не «не слишком потертый»)*.
* `Take your time` $\rightarrow$ «не торопись, не спеши» *(не «возьми свое время»)*.

## 4. Сквозная проверка батчами по 100 слов (Cross-Lingual Batch Workflow)

### 4.1. Почему сквозной срез эффективнее проверки по отдельным языкам
1. **Эффект взаимной верификации (Cross-Language Outlier Detection):**  
   Когда строка из 36 переводов одного английского слова выводится в одну матрицу, любая аномалия полисемии (например, 35 языков перевели *«кран»*, а один язык перевел *«птица журавль»*) выявляется моментально.
2. **Частотный приоритет (CEFR Framework):**  
   Проверка идет сверху вниз: ID 1–100, 101–200, 201–300. Первые 1 500 слов — это база приложения (A1–B1), с которой каждый день работают 100% пользователей.

### 4.2. Алгоритм работы с батчем
1. **Экспорт батча:** Запуск скрипта выгрузки 100 слов с 36 переводами в матричный вид.
2. **Семантический анализ:** Проверка полисемичных слов на соответствие смыслу карточки/урока.
3. **Грамматический фильтр:** Проверка глаголов на инфинитив, идиом на отсутствие калек.
4. **Применение калибровок:** Запись обновлений в `frontend/assets/data/words.json`, `assets/data/words.json`, `docs/assets/data/words.json`.
5. **Сборка и тесты:** Запуск `node scripts/build.cjs` и `npm test` (71 тест).
6. **OTA-синхронизация:** Обновление документа `shared/vocabulary_updates` в Cloud Firestore с обязательным контролем лимита 1024 КБ.

## 5. Автоматизированный пайплайн контроля качества (Quality Gate Pipeline)

Любой аудит считается успешно завершенным **только при выполнении 4 условий**:

1. **Матрица здоровья (True Health Matrix):**  
   0 пропусков, 0 скобок, 0 точек с запятой, 0 слэшей, 0 дубликатов по всем 35 языкам перевода (в английском — только 6 лемм-источников).
2. **Сборка бандлов (`node scripts/build.cjs`):**  
   Синхронизация исходников, 0 поврежденных символов U+FFFD, валидация JS/HTML.
3. **Регрессионные тесты (`npm test`):**  
   Все **71 тест проходят со 100% успехом** (включая Gate 1b live probe app-ads.txt, Gate 3 completeness, Leaderboard E2E, AdService).
4. **Лимит Cloud Firestore OTA:**  
   Размер документа `shared/vocabulary_updates` строго **меньше 1048576 байт** (< 1024 КБ). При необходимости — безопасная очистка устаревших избыточных записей, идентичных базовому бандлу.
