# Инструкция по выкатке рейтингов и правил безопасности (Rollout Plan)

Данный документ описывает точный порядок и регламент развёртывания обновлений системы рейтингов («Лига недели» и «Общий зачёт») и правил безопасности Firestore в проекте **my-duolingo**.

---

## 1. Порядок выкатки (Пошаговый регламент)

### Шаг 1. Очистка orphaned-аккаунтов (`scripts/purge_orphans.mjs`)
* **Цель**: Полностью удалить данные скрытых в коде аккаунтов (`b9Puaf5jtthwQlOPvAdZJ1o5CBC3` и `jf0lHNZnwXVKzQpNh1FSYwkrDfl1`) из всех коллекций Firestore.
* **Предварительное условие**: В консоли Firebase Authentication убедиться, что оба UID действительно отсутствуют в списке пользователей (или деактивированы). В Firestore Console при необходимости создать индекс Single Field Override для группы коллекций `players` по полю `userId` (Scope: Collection group).
* **Команды**:
  1. Dry-run проверка:
     ```bash
     node scripts/purge_orphans.mjs
     ```
     Скрипт проверяет статус в Firebase Auth и выводит список документов в `players`, `leaderboard_alltime` и `users/{uid}/*`.
  2. Удаление документов:
     ```bash
     node scripts/purge_orphans.mjs --apply
     ```
     *(Если аккаунт всё ещё существует в Auth, скрипт потребует дополнительный флаг `--force`)*.

---

### Шаг 2. Миграция общего словаря (`scripts/migrate_shared_vocabulary.mjs`)
* **Цель**: Скопировать глобальные словарные обновления из приватного документа администратора `users/wB3NVAmBarXHSBrtEzDCriS0XBy2/data/vocabulary_updates` в общую коллекцию `shared/vocabulary_updates` (доступную всем на чтение и только администратору на запись).
* **Команды**:
  1. Dry-run проверка:
     ```bash
     node scripts/migrate_shared_vocabulary.mjs
     ```
  2. Применение миграции:
     ```bash
     node scripts/migrate_shared_vocabulary.mjs --apply
     ```

---

### Шаг 3. Деплой правил Firestore из ветки `fix/leaderboard-v2`
* **Цель**: Активировать правила безопасности с поддержкой `leaderboard_alltime`, проверкой `email_verified == true`, валидацией `weekKey`, ограничением скорости записи (3 XP/с + 150) и закрытием доступа к приватным данным.
* **ВАЖНО**: Деплоить правила строго из ветки **`fix/leaderboard-v2`** (не из ветки `main` и не из устаревшей ветки `android`).
* **Команда**:
  ```bash
  firebase deploy --only firestore:rules
  ```

---

### Шаг 4. Деплой веб-клиента (немедленно после шага 3, минуты, не часы)
* **Цель**: Выкатить новую версию фронтенда, которая отправляет атомарный commit с записью в `leaderboards/{week}/players/{uid}` и `leaderboard_alltime/{uid}`, передаёт `weekKey` и поддерживает UI подтверждения email.
* **Почему сразу**: Новый клиент при начислении очков всегда пишет в `leaderboard_alltime`. Если задеплоить клиент до правил, старые правила вернут 403 на этот путь. Поэтому сначала деплоятся правила, а сразу следом — клиент.
* **Команды**:
  1. Сборка и синхронизация версий (`?v=385.0`):
     ```bash
     node scripts/build.cjs
     ```
  2. Деплой хостинга:
     ```bash
     firebase deploy --only hosting
     ```
     *(или push в ветку деплоя GitHub Pages / продакшн-хостинга)*.

---

### Шаг 5. Заполнение «Общего зачёта» (`scripts/migrate_alltime.mjs`)
* **Цель**: Собрать исторический XP игроков по всем прошедшим неделям из `collectionGroup('players')` и заполнить коллекцию `leaderboard_alltime/{uid}`.
* **Особенность**: Клиент при первом входе ограничен созданием не более 10 000 XP в `leaderboard_alltime` по соображениям безопасности. Скрипт через Admin SDK выставляет `totalXp = Math.max(currentTotal, sumWeeklyXP)`, восстанавливая полный баланс игрокам со стажем > 10 000 XP без занижения чьих-либо очков.
* **Команды**:
  1. Dry-run отчёт (показывает количество игроков и добавляемый XP):
     ```bash
     node scripts/migrate_alltime.mjs
     ```
  2. Применение:
     ```bash
     node scripts/migrate_alltime.mjs --apply
     ```

---

### Шаг 6. Сборка и релиз Android APK / AAB
* **Цель**: Доставить обновлённую версию приложения пользователям Android (Capacitor).
* **Репозиторий**: Ветка `fix/leaderboard-v2-android` (синхронизирована с `fix/leaderboard-v2`).
* **Команды сборки**:
  1. Синхронизация веб-бандла:
     ```bash
     node scripts/build.cjs
     npx cap sync android
     ```
  2. Сборка релизного бандла:
     ```bash
     cd android
     ./gradlew bundleRelease
     ```
     *(или сборка APK через `node scripts/build_android_apk.mjs`)*.
  3. Публикация AAB в Google Play Console.

## 2. Что видит пользователь на каждом этапе

1. **До обновления клиента в открытой вкладке браузера**:
   * В приложении `sw.js` **не кэширует** JS-скрипты приложения. Однако если у пользователя открыта вкладка браузера со старым загруженным кодом, при начислении очков после деплоя правил он получит 403 от Firestore.
   * При перезагрузке страницы или открытии приложения браузер сразу загружает свежий JS-бандл (версия `?v=385.0`).
2. **Пользователь с неподтверждённым email**:
   * При входе в систему и на экране рейтинга видит дружелюбное уведомление: *«Для участия в рейтинге подтвердите email. Проверьте ваш почтовый ящик»*.
   * На экране рейтинга отображается баннер с кнопками *«Отправить ещё раз»* и *«Я подтвердил»*.
   * До подтверждения очки в таблицу лидеров не попадают. После клика по ссылке в письме и нажатия *«Я подтвердил»* токен принудительно обновляется, баннер исчезает, а очки синхронизируются.
3. **Игрок с историей > 10 000 XP**:
   * До запуска Шага 5 (`migrate_alltime.mjs`) видит в «Общем зачёте» 10 000 XP (потолок создания документа правилами).
   * После запуска Шага 5 (`--apply`) видит свой полный исторический счёт.
4. **В понедельник 00:00 UTC**:
   * «Лига недели» обнуляется у всех игроков без исключения.
   * Очки прошлой недели не переносятся в новую неделю (удалены plain `xp`, `calcXp` и fallback).
   * «Общий зачёт» сохраняет все набранные за всё время очки.

## 3. Чеклист проверки после выкатки (Post-Rollout Verification)

- [ ] **Новый пользователь**: Зарегистрироваться по email/паролю -> проверить отправку письма -> при входе увидеть уведомление о верификации -> подтвердить email -> заработать XP -> проверить попадание в топ Лиги недели и Общего зачёта.
- [ ] **Email-пользователь без подтверждения**: Зайти в аккаунт -> увидеть уведомление при входе и баннер в рейтинге -> нажать «Отправить ещё раз» (получить письмо) -> после перехода по ссылке нажать «Я подтвердил» -> убедиться, что баннер скрылся и очки появились в рейтинге.
- [ ] **Игрок со стажем**: Открыть вкладку «Общий зачёт» -> проверить, что отображается полный счёт XP (включая значения свыше 10 000 XP).
- [ ] **Смена недели**: Убедиться, что в начале новой ISO-недели (понедельник 00:00 UTC) недельный XP у всех игроков равен 0, а старый `localStorage['xp']` не подмешивается.
- [ ] **Безопасность**:
  - `GET /users` (list) возвращает 403 (доступ запрещён).
  - Чужие заметки `users/{otherUid}/data/notes` недоступны на чтение без авторизации владельца (403).
  - Приватные данные администратора закрыты от чтения.
  - Документ `shared/vocabulary_updates` доступен всем пользователям для чтения.
- [ ] **Android APK**: Установить свежий APK/AAB -> проверить работу рейтинга и синхронизацию очков.
